# 头像上传与个人资料编辑

Status: ready-for-human（2026-09-02：`01` 已 resolved，`02` / `03` 实现与自动化验证均已完成。服务端联调 **229 项**全绿，前端单测 17 项通过，构建通过。**仅剩浏览器冒烟**——Chrome 的 CDP 端点失效，且重启浏览器会关掉正在看的标签页，故留给人工，步骤见 `issues/02` 与 `issues/03` 的 Comments）

## 问题陈述（Problem Statement）

`User.avatar` 打从 Web IM 起就是硬编码的 `'default'`，从来没用过。界面上所有头像——会话列表、搜索结果、消息气泡、资料卡、群成员列表——渲染的全是**昵称首字母方块**。所有人长得一模一样，群聊里尤其分不清谁是谁。

想换头像也无处下手：没有上传入口，也没有改昵称的接口。

这是 ROADMAP 的 **B3**。它此前唯一的阻塞点是「改头像后历史消息气泡里的头像跟不跟随」，已于 2026-09-01 定为**跟随**（回查 `users` 表，多一次查询换全局一张脸）。

## 解决方案（Solution）

复用既有的上传能力（`POST /chat/upload` 与 A3/A4 的目录治理、所有权校验）新增一种 `avatar` 类型，再加一个 `PATCH /chat/me` 改昵称与头像；前端在各处渲染头像时**有图显图、无图回退首字母**。

**服务端改动面比看上去小**，这是动手前核清的关键事实：

| 读取路径 | 头像来源 | 是否要改 |
| --- | --- | --- |
| 会话列表（`sessions`） | `users` 表 / `groups` 表，无注册记录才回退快照 | **不用改**（已跟随） |
| 群成员列表（`GroupMemberDTO`） | `users.avatar` | **不用改**（已跟随） |
| **历史消息气泡（`HistoryMessageDTO.senderAvatar`）** | `ChatMessage.mine.avatar` **快照** | **要改** |

也就是说，「跟随」这条决策真正要动的只有**历史消息一处**。

## 词汇决策（Domain vocabulary）

**不引入新词**，沿用 `CONTEXT.md` 的既有词汇：**用户**、**头像**、**群**、**成员**、**联系人**。

**Avoid（避免）：**

- **「头像快照」当成可选优化** —— 消息里存的是发送时的头像快照，这是历史事实，不是缓存；「跟随」指的是**展示时按发送者回查 `users` 表**，不是把快照改掉
- **「头像同步」「实时更新」** —— 本期**不做**实时通知（见「已知上限」），不要让人以为改了头像别人立刻就能看到
- **「默认头像库」** —— 本期只有首字母回退，没有内置头像图集

**`CONTEXT.md` 无需改动**（「头像」已在 `User` 词条里）。

## 用户故事（User Stories）

1. 作为用户，我希望上传自己的头像，以便别人能一眼认出我
2. 作为用户，我希望改昵称，以便换了称呼后群里显示的是新名字
3. 作为用户，我希望在会话列表、气泡、资料卡、群成员列表里看到的头像是一致的，以便不出现「列表一张脸、气泡另一张脸」
4. 作为群创建者，我希望改群头像，以便群也有辨识度
5. 作为用户，我希望上传大图时不用自己先压缩，以便随手选一张就能用
6. 作为用户，我不希望有人能改别人的头像或昵称

## 实现决策（Implementation Decisions）

### 服务端

- **`UploadRules` 新增 `avatar` 规则**：`jpg / jpeg / png / webp / gif`，≤ **2MB**。
  集中配置点已有，加一条即可；`rule(for:)` 加一个 `case "avatar"`。**上传接口不用改**，`POST /chat/upload` 照旧，只是多一种 `msgType`
  - 允许 gif：动图头像是常见需求；但会占用更多空间，2MB 上限已经兜住
- **新增 `PATCH /chat/me`**（`tokenProtected`），可改 `nickname` 与 `avatar`，两者至少给一个，否则 400
  - 昵称 trim 后判空（与建群时的群名校验一致）
  - 只改自己，没有改别人的能力
  - 返回更新后的 `UserInfo`
- **历史消息的 `senderAvatar` 改为按 `senderUserId` 回查 `users` 表**（决策：跟随）
  - 命中就用 `users` 表的权威头像；**无注册记录时回退消息里的快照**——这正是快照存在的意义
  - `senderNickname` 同步按 `users.nickname` 优先（同一套逻辑，别只改头像不改昵称，否则又是一种不一致）
  - 代价：历史接口多一次 `users` 查询。可接受（头像不是每帧都要变的字段）
- **群头像不用改服务端**：`PATCH /chat/groups/:id` 早已支持 `avatar`（B7 故意留着没用），前端传进去就行

### 前端

- `api.ts` 新增 `updateMe(token, { nickname?, avatar? })`；头像上传复用既有的 `uploadMedia(token, file, 'avatar')`
- **选图后在前端压缩**：用 canvas 把最长边压到 **256px** 再上传。
  理由：会话列表一次渲染几十个头像，直接用原图（上限 10MB）会让列表卡死。服务端没有图像处理库，压缩只能放在前端
  - **gif 不压缩**（canvas 会丢动画），直接传，靠 2MB 上限兜底
  - 输出格式：png/jpeg/webp 输出为 `image/jpeg`（体积最小）；带透明通道的 png 输出 `image/png`
- 资料卡里加入口：点自己的头像 → 选图；昵称可编辑
- **各处头像渲染改为「有图显图、无图回退首字母」**，共 5 处：会话列表、搜索结果、消息气泡（发送者）、资料卡、群成员列表
  - 加载失败（`onerror`）也要回退首字母——头像文件可能被清掉，裂图比字母块难看得多
- 群头像：创建者在群信息弹窗里可改（复用 B7 的 `updateGroup`），非创建者看不到入口
- 不引依赖：压缩用浏览器原生 canvas，不装图像库

### 已知上限（本期接受）

- **改头像/昵称/群头像都不实时通知别人**，对端要刷新才看得到（与 B7 的改名、拉人一致）。**这是本功能连续第三个接受「无实时通知」的地方**，见「补充说明」
- **孤儿文件**：每次换头像都会在 `Public/uploads/` 留下一个再无引用的文件。A3 的清理策略本来就未做，B3 会让它加速恶化。**本期不解决**，但要在 spec 里记一笔
- 不做头像裁剪 UI（只压缩不裁剪）；不做默认头像图集

## 测试决策（Testing Decisions）

- 服务端联调 `web/e2e-check.mjs`：**现有 214 项须全绿**（回归基线）。新增用例：
  - `POST /chat/upload` 用 `msgType=avatar` 上传成功返回 URL
  - 头像格式不支持 / 超 2MB 被拒（沿用既有的 415 / 400 语义）
  - `PATCH /chat/me` 改头像与昵称成功；两者皆空 400；昵称空白 400；未带 token 401
  - **改头像后历史消息气泡里的头像跟着变**（跟随决策的核心用例，必须有）
  - 无注册记录的发送者仍回退消息快照（不能因为查不到就把头像变空）
  - **改头像后会话列表与群成员列表的头像同步**（这两处本来就跟随，用来守住回归）
  - 群头像：创建者能改、非创建者 403
- 前端：`npm run build` 与 `npm test` 通过
- 冒烟：上传一张大图 → 列表/气泡/资料卡都显示新头像；刷新后仍在；换回默认时回退首字母

## 超出范围（Out of Scope）

- **孤儿头像文件回收** —— 归入 A3 / C2 的遗留，不在本期。但要意识到 B3 会让这个问题变多
- **服务端图像缩放** —— Vapor 侧没有图像库，压缩放前端
- **头像裁剪 UI** —— 只压缩，不裁剪
- **默认头像图集** —— 仍是首字母回退
- **实时通知头像变更** —— 见「已知上限」
- **改密码、改账号** —— 没有用户故事要求

## 补充说明（Further Notes）

- 阻塞：无硬前置（A3、A4 均已 resolved）
- **与 B7 的关系**：群头像直接复用 B7 加的 `updateGroup` 与 `GroupSummary` 里的 `ownerId`，接口层零改动
- **一个值得单独讨论的观察**：这是连续第三个接受「变更不实时通知」的功能——B7 的改群名、B7 的拉人入群、B3 的改头像。三次都在 WS 协议里克制地不加帧，理由都成立（刷新即可看到，代价是短暂的界面滞后）。但三次之后，值得问一句：是不是该有一个**通用的「实体变更」广播机制**，而不是每个功能各自判断一遍？
  本功能**不为它铺路**（YAGNI），但如果出现第四个，就该认真考虑抽一层了
