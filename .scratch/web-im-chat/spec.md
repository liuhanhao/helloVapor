# Web 版 IM 聊天（Web 先跑通）

Status: ready-for-agent

## 问题陈述（Problem Statement）

helloVapor 目前只有 iOS 客户端，用户离开 iPhone 就无法收发消息。服务端虽然把消息存入了数据库，但从未把消息推送给接收方——消息只进不出；媒体消息（图片/音频/视频）完全没有支持；文件上传下载接口硬编码了单一文件。想要在任何设备上聊天，必须补上 Web 端，并把服务端的消息流转真正打通。

## 解决方案（Solution）

构建一个独立的 Web 聊天客户端（会话列表 + 聊天窗口），用户注册/登录后即可与任意用户一对一聊天：发送文本（含 Unicode emoji）、图片、音频、视频。服务端扩展为真正的消息中转：收到消息后入库并实时推送给在线接收方；提供文件上传（按类型校验）与静态文件访问；提供会话列表与历史消息查询，刷新不丢记录。iOS 端本次不改动，但协议向前兼容，两端收发的文本消息可互通。

## 用户故事（User Stories）

1. 作为一个访客，我希望在 Web 登录页注册新账号（昵称、账号、密码、确认密码），以便开始使用聊天系统
2. 作为一个访客，我希望用账号密码登录，以便以我的身份进入聊天系统
3. 作为一个访客，我希望登录失败时看到明确的错误提示，以便知道是账号还是密码的问题
4. 作为一个已登录用户，我希望看到左侧会话列表，展示我与各联系人的最近一条消息和时间，以便快速找到要继续的对话
5. 作为一个已登录用户，我希望点击会话列表中的某个联系人，右侧打开与他的聊天窗口，以便查看和发送消息
6. 作为一个已登录用户，我希望能主动发起与一个新用户的会话（输入对方账号或 userid），以便和还没有聊天记录的人对话
7. 作为一个已登录用户，我希望发送文本消息后，消息立即出现在我的聊天窗口中（右侧气泡），以便确认发送成功
8. 作为一个已登录用户，我希望对方在线时能实时收到我的消息（左侧气泡），以便进行即时对话
9. 作为一个已登录用户，我希望通过输入框旁的 emoji 面板选择 Unicode emoji 并随文本发送，以便表达情绪
10. 作为一个已登录用户，我希望选择本地图片发送，对方能看到图片缩略图并可点击查看原图，以便分享图片
11. 作为一个已登录用户，我希望选择本地音频文件发送，对方能直接在聊天窗口播放，以便分享语音
12. 作为一个已登录用户，我希望选择本地视频文件发送，对方能直接在聊天窗口播放，以便分享视频
13. 作为一个已登录用户，我希望选择超大文件或非法类型时得到明确的拒绝提示，以便知道为什么发送失败
14. 作为一个已登录用户，我希望重新打开某个会话时能看到历史消息，以便接续之前的对话
15. 作为一个已登录用户，我希望刷新页面后登录状态和会话列表不丢失，以便随时回到聊天
16. 作为一个已登录用户，我希望收到新消息时会话列表的顺序和最后一条消息自动更新，以便不错过新对话
17. 作为一个已登录用户，我希望退出登录后回到登录页且本地凭证被清除，以便保护账号安全
18. 作为一个 iOS 用户（既有能力不受破坏），我希望 iOS 客户端发出的文本消息依然正常入库，以便现有功能不被本次改动破坏

## 实现决策（Implementation Decisions）

### 总体架构

- Web 端为独立前端工程（Vue 3 + Vite + TypeScript），与 Vapor 服务端前后端分离。详见 ADR-0001
- 开发期前端开发服务器代理后端请求，避免跨域；服务端同时启用 CORS 中间件作为兜底
- 术语遵循根目录 `CONTEXT.md` 词汇表（用户 / 会话 / 消息 / 消息类型 / 媒体消息 / 联系人 / token）

### 服务端（hello/）

**协议扩展（遵循 ADR-0002：扩展现有协议而非重新设计）**
- WebSocket 消息沿用现有 `type` / `data.mine` / `data.to` 结构，在 `data.mine` 内新增 `msgType` 字段：`text`（含 Unicode emoji）/ `image` / `audio` / `video`
- 未携带 `msgType` 的消息按 `text` 处理，保证 iOS 端现状兼容
- 媒体消息的 `content` 字段存服务端返回的文件 URL

**消息路由推送（核心补齐）**
- 服务端收到消息入库后，查找接收方的在线连接并将消息原文推送给它；同时回送发送方一份确认（含服务端时间戳），替代现有"反转回显"的占位逻辑
- 接收方离线时不推送、不报错，消息仅入库，靠历史查询接口补回
- 连接仍沿用现有查询参数携带身份（本次不接入 token 鉴权）

**文件上传与访问**
- 上传接口改为标准 multipart 表单：按 `msgType` 校验类型与大小——图片（jpg/png/gif/webp）≤10 MB，音频（mp3/m4a/aac/wav）≤20 MB，视频（mp4/mov）≤100 MB；超限或非法类型返回明确错误
- 文件以 UUID + 原扩展名存入独立上传目录，上传接口返回可访问的文件 URL
- 开启静态文件服务，托管上传目录与前端产物无关的静态资源；替代现有硬编码单一文件的上传下载接口

**持久化查询接口（新增）**
- 会话列表接口：按当前用户聚合与其相关的消息，按联系人分组返回对方身份信息与最后一条消息（内容预览 + 时间），按最后消息时间倒序
- 历史消息接口：按当前用户与指定联系人返回双方消息，按时间正序，支持分页
- 消息表新增 `msgType` 字段的迁移

### 前端（新建独立工程）

- 技术栈：Vue 3 + Vite + TypeScript；状态管理用 Pinia；路由用 Vue Router
- 图标按需从 koboyo.com/icons 下载 SVG 放入工程静态资源，不引入图标库依赖
- 页面结构：登录/注册页；主界面为左侧会话列表 + 右侧聊天窗口
- 聊天窗口：消息流按 `msgType` 渲染（文本气泡 / 图片缩略图可点大图 / 音频播放器 / 视频播放器）；输入区含文本输入框、emoji 选择面板（输出 Unicode 字符）、媒体文件选择按钮
- 发送媒体流程：先调上传接口拿到文件 URL，再以媒体消息协议发出
- 实时通信：登录后建立 WebSocket 连接；收到消息按归属更新聊天窗口或会话列表
- 凭证（token 与用户信息）存 localStorage，刷新后自动恢复登录态并拉取会话列表
- 会话列表新消息实时置顶更新；未读计数本期不做

### 数据库

- `message` 表新增 `msgType` 字段（字符串，默认值兼容旧数据按 text 解读）
- 不新增其他表；联系人关系由消息推导，不建好友关系表

## 测试决策（Testing Decisions）

- 本次不写自动化测试（用户明确决定），全部通过手工验证
- 服务端手工验证：启动服务后依次验证注册 → 登录 → 上传三类文件（含超限与非法类型拒绝）→ 两个连接互发消息实时收到 → 会话列表与历史查询返回正确
- 前端手工验证：登录/注册流程、三类媒体发送与对端渲染、emoji 面板、刷新恢复、新消息置顶
- 端到端互通验证：iOS 客户端发出的文本消息在 Web 端可见，反之亦然
- 自动化测试作为后续任务另开

## 超出范围（Out of Scope）

- iOS 端的媒体消息发送/接收改造（协议已预留，后续任务）
- 群聊（服务端已有 group 类型字段，但本次仅单聊）
- WebSocket 与 HTTP 接口的 token 鉴权（本次不鉴权，后续任务；需重点补上）
- 好友关系与添加好友流程（联系人由消息推导）
- 未读消息计数、消息推送通知（离线推送）
- 消息撤回、删除、转发
- 头像上传与个人资料编辑
- 部署与生产环境配置

## 补充说明（Further Notes）

- 现有服务端消息只入库不推送、上传接口硬编码 `666.jpg`，均在本规格内一并解决
- 服务端连接表当前为进程内字典，单实例部署假设成立；多实例扩展超出范围
- 文件体积上限（10/20/100 MB）为访谈默认值，实现时以常量集中配置，便于后续调整
- 后续任务队列建议顺序：WS 鉴权 → iOS 媒体消息 → 群聊
