# 2026-11-12

## 把 hello/Package.swift 的 Swift 工具链版本对齐本机 6.4.2

- 本机：`Apple Swift 6.4.2` / `Swift Package Manager 6.4.2`（macOS 26.7.2, arm64），Xcode 工具链。
- 改动 `hello/Package.swift`：
  - `// swift-tools-version:5.6` → `// swift-tools-version:6.4`
  - 新增 `swiftLanguageModes: [.v5]`（放在 `targets` 之后，Package 初始化器参数顺序要求）。
- 原因：只改 tools-version 到 6.4 会默认启用 Swift 6 语言模式，`swift build` 报 17 条严格并发错误，集中在
  `routes.swift`（全局 `var application` 非并发安全）、`Models/Upload|User|UserToken.swift`
  （`@ID` 宏生成的 `_id` 可变存储属性、`ModelAuthenticatable` / `ModelTokenAuthenticatable` 静态 keypath
  被推断为 `any KeyPath<...> & Sendable` 而不 conform）。属于 Vapor 4 / Fluent 框架层面未适配，非业务代码问题，
  不改源码，显式保持 Swift 5 语言模式。
- 验证：`swift build --disable-sandbox` → `Build complete!`，0 error，仅剩余原有的
  `Application(env)` deprecation 等 warning；`dump-package` 确认 `toolsVersion: 6.4.0`、
  `swiftLanguageVersions: ["5"]`。
- 坑：`swift-tools-version` 是 SwiftPM 清单格式版本，不是编译器版本号；写 `6.40` 会被解析成 `6.40.0`
  并因高于本机 6.4.2 被拒。合法写法是 `6.4`。本机 SwiftPM 实测接受 5.6 / 6.0 / 6.1 / 6.2 / 6.3 / 6.4。
- 依赖锁定：Vapor 4.122.0（其自身 Package.swift 为 `swift-tools-version:6.0`），Fluent 同 6.0。
  项目平台约束仍是 `.macOS(.v12)`，Linux 不可构建。
- **遗留风险**：`.github/workflows/e2e.yml` 用 `runs-on: macos-latest` 且未固定 Xcode/Swift 版本，
  `swift build` 未带 `--disable-sandbox`。tools-version 6.4 要求 CI runner 的 SwiftPM ≥ 6.4，
  若 GitHub macOS runner 仍停留在 Swift 6.0/6.1，E2E 会直接报 tools version 过高。需要固定 Xcode 26.x
  或改用 swiftly 安装 6.4.x。本次未改动 CI 文件。
- 沙箱提示：本机跑 `swift package` / `swift build` 时 SwiftPM 的 `sandbox-exec` 会被工具沙箱拦
  （`sandbox_apply: Operation not permitted`），加 `--disable-sandbox` 即可。
